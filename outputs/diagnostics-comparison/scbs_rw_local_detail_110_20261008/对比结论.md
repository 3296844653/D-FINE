# 110轮 RW Local Detail 诊断结论

结论：在置信度0.5、IoU0.5下，write有局部正向响应；但整体AP、中尺度AP、hand/read AP没有改善，因此目前不能将此模块视为有效的整体改进，更不能据此确认Decoder是唯一瓶颈。

## 数据核对

RW诊断完整覆盖1026张验证图片、5427个GT、307800个query（每图300）。
配置为110轮、停止增强100轮、batch32，局部模块开启，不叠加AQS；使用自己的best_stg2.pth EMA。
诊断COCO AP=54.92154，与训练日志整体AP最优epoch102的结果一致。

本地标注与Baseline Run2诊断记录的SHA256一致：
`623bb8478049dd69d32a92183b0a322bdb8f79f72e6f6f52e491d48923bd5d37`。
RW权重导出指纹为`4489ce0ee4d2bc4c29bac826fc973278757efef3384051976e471202ed6ba065`。
标注类别为0=hand-raising、1=read、2=write；双方验证变换一致。

## 一、整体检测结果

所有AP/AR以百分数表示，Δ为百分点；采用各实验自己的整体AP最优权重。

| 指标 | Baseline Run2 | RW Local Detail | Δ |
| --- | ---: | ---: | ---: |
| AP | 55.05 | 54.92 | -0.13 |
| AP50 | 72.16 | 72.19 | +0.03 |
| AP75 | 62.18 | 62.15 | -0.03 |
| APm | 41.14 | 39.81 | -1.33 |
| APl | 56.96 | 56.92 | -0.04 |
| AR100 | 83.57 | 83.60 | +0.02 |
| hand AP | 59.34 | 58.68 | -0.67 |
| read AP | 58.19 | 57.74 | -0.45 |
| write AP | 47.61 | 48.35 | +0.74 |

对比你提供的110轮三次基线均值：AP 55.16→54.92（-0.24），
read AP 58.06→57.74（-0.32），write AP 48.50→48.35（-0.15）。
因此，不能只选write AP较低的Run2作为参照，就宣称模块稳定提升writing。
单次模块实验还不能判断重复性。

## 二、固定阈值下write确实有改善

这是原Validator的类别无关、最高IoU贪心一对一诊断，置信度0.5、IoU0.5；不是COCO AP。

| 诊断项 | Baseline Run2 | RW Local Detail | Δ |
| --- | ---: | ---: | ---: |
| write→read | 250 | 218 | -32 |
| read→write | 168 | 170 | +2 |
| write正确匹配 | 363 | 395 | +32 |
| write Precision | 38.95% | 43.12% | +4.17个百分点 |
| write Recall | 53.07% | 57.75% | +4.68个百分点 |
| hand正确匹配 | 1826 | 1801 | -25 |
| read正确匹配 | 1890 | 1898 | +8 |
| 所有正确类别匹配 | 4079 | 4094 | +15 |
| 所有类别误判 | 461 | 420 | -41 |
| 未匹配GT | 887 | 913 | +26 |
| 未匹配预测 | 2697 | 2629 | -68 |

所以它不是“完全没有响应”：writing在这一工作阈值下更好，但不是双向读写混淆同时改善。
hand未匹配GT由460增加到490，是整体未匹配GT上升的重要部分。
净减少32个write→read不等于已经逐项确认同样32个GT被纠正；框、分数及匹配都可能改变。
未匹配预测也不等于已经人工确认的背景误检。

## 三、APm下降主要不是writing造成

下面从双方已有COCO eval.pth中读取类别×尺度精度张量，maxDets=100；不使用0.5置信度截断。

| medium类别 | GT数 | Baseline Run2 AP | RW AP | Δ |
| --- | ---: | ---: | ---: | ---: |
| hand | 324 | 43.07 | 40.99 | -2.07 |
| read | 332 | 47.86 | 46.38 | -1.48 |
| write | 57 | 32.50 | 32.06 | -0.44 |

三个medium类别均无改善，hand/read下降更明显。
large writing AP则从49.14升到49.90（+0.75），说明相对Run2的writing改善主要在large组，不能说模块解决了中尺度细节不足。
small只有3个GT、2张图，每类各1个；APsmall的跳变不宜作为有效证据。
尺度按原图COCO area分组，不是缩放到640后的框面积；medium writing仅57例，也需要谨慎解释。

即使新增logit只直接修正read/write，训练中的共享特征、原匹配和梯度仍可改变hand与bbox。
所以hand退化并不证明类别掩码或代码冲突；现有输出也不能确定共享梯度是根因。

## 四、writing的剩余缺口

RW模型的684个writing GT均有IoU≥0.5的query候选；97.37%有IoU≥0.75候选。
这是全部query的oracle覆盖，不是模型真正检测Recall，也不证明定位已经完全解决。

真正要分开的候选证据是：

- 472个writing GT存在后处理选中的高分同类候选。
- 212个不存在：所有重叠query的write分数都低于0.5。并非全都是“类别正确、仅分数偏低”。
- 其中best-IoU类别正确但低分、且没有其他高分同类候选的B组为75个。
- best-IoU第一类别错误、且没有其他高分同类候选的D组为137个。
- medium writing有57个GT，其中27个没有高分同类候选。

因此仍然是“有几何候选，但不能充分转化为可靠writing预测”的问题，兼有类别判别与评分不足。
B/D不是COCO FN的等价定义，也不能自动排除标注错误、遮挡、相邻目标等因素。

Baseline Run2文件只有混淆矩阵和COCO评估，没有全query导出，不能与它逐项比较B/D变化。
不要把这些RW候选统计误当成已经完成了Run2配对因果分析。

## 下一步判断

目前应保留AQS作为有整体AP正信号的候选，RW Local Detail暂不直接与它叠加训练。
若继续查这个局部分支，优先对同一个RW checkpoint做分支开启/关闭的冻结推理对照，
看局部修正本身的贡献；比再完整重训一个参数组更直接。
即便这项对照有效，也不能抹掉当前整个训练方案相对多次基线均值没有提升的事实。
现有统计还不能判定问题具体发生在采样位置、attention、特征内容还是训练耦合。

完整RW分析已生成在本目录的summary.txt、coco_per_class_and_size.json、
best_query_cross_classification.json与gt_records.jsonl中。无需再训练或重新导出。
